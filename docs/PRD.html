二、背景与目标

2.1 背景

发起人是软件工程专业在校学生，本身是该产品的第一个真实用户。日常学习（专业课程、竞赛备考、自学新技术）中同时暴露三个问题：

  • AI 每次从零开始讲。同一模型对"什么是特征值"的回答，对零基础和对学过线性代数的人完全一样。用户每次都要手动交代背景（"我已经会 X 了，直接讲 Y"），这是纯粹的重复劳动。
  • 讲完即忘，没有沉淀。对话是一问一答的流水，学完的东西散在几十条消息里，无法整理成可复习、可导出的笔记；下一次遇到同一概念，等于重新学。
  • 学习材料无法结构化。看视频、读 PDF 是被动输入，无法定位"这段讲了什么知识点"、无法标注"这里我没懂"、无法把材料转成可测可复习的讲义。

结论：市面 AI 学习工具解决的是"讲得出来"，没有解决"讲给谁"和"讲完之后"。本项目的差异化只有一个——让 AI 拥有一份持续更新的「学习者知识画像」，并以它为基础决定怎么讲、讲多深、什么时候提醒复习。

2.2 目标

目标层级目标描述衡量方式
产品目标让同一概念在第二次、第三次学习时，AI 的讲解明显区别于第一次（更贴合当前水平）画像覆盖率 + 讲解采纳率（见 2.3）
用户目标用户不需要再手动交代"我会什么"，且学完的知识能带走笔记产出率 + 划词入库率
项目目标（个人）先自用跑通闭环，2 周 dogfooding 后决定是否继续投入后续版本连续使用天数 + 闭环完成次数

三、名词与术语定义

术语定义
知识画像系统对用户掌握情况的显式建模结果，由若干「画像条目」组成，每条对应一个知识点及其掌握度、证据来源、最近接触时间
画像条目最小记忆单元：{知识点, 掌握度 0–1, 证据来源列表, 最近接触时间, 状态}
知识点可独立讲解的概念单元（如"导数""特征值""TCP 三次握手"），含所属领域与前置依赖关系
前置依赖讲解知识点 X 之前建议先具备的知识点集合，用于判断是否需要补基础
掌握度0–1 的数值，表达对该知识点的掌握概率估计；初始规则见 FR-03
讲解深度档L0 一句话＋类比｜L1 定义＋例子｜L2 原理＋推导｜L3 数学形式＋边界＋反例
消息修订用户编辑某条历史消息，触发后续 AI 响应基于新内容重新生成；旧响应折叠保留
结构化讲义由对话或素材生成的可复习文档，含标题、总结、核心概念、例子、误区、延伸问题，每条带溯源锚点
溯源锚点讲义条目到原始位置的引用指针（对话消息 ID 或页码/时间戳），点击可跳回原文
划词用户在阅读视图内选中一段文本，触发即时解答浮层
主动任务系统在用户未发起请求时生成并推送的辅助动作（复习提醒、讲后小结等），受行为约束与频控限制
降级主链路能力不可用时的退路方案（如模型超时 → 返回历史缓存讲解而非报错）
Token 预算单会话可消耗的模型 token 上限，超限时压缩注入的画像与历史上下文

4.3 明确不做（Won't）

以下项目本期及可见未来不做，防止范围蔓延：

  • 多用户 / 多租户 / 权限矩阵——个人项目无第二个角色，做成"可开放注册"会引入数据隔离、权限校验、计费等一整套成本，且对验证核心假设零帮助。
  • 移动端 App / 浏览器插件 / 多端同步——同步冲突处理是独立的工程课题，MVP 阶段 Web 单端足够验证价值。
  • 支付 / 订阅 / 商业化——本期无商业模式假设。
  • 社区、分享、UGC 内容广场。
  • 多语言 / 国际化——界面中文，内容按用户提问语言回答。
  • 预置全学科知识图谱——通用学科的图谱不可能人工建全，改为「按需自生长」（见 5.3 推荐方案）。

五、方案对比与选型说明

本产品全部差异化的技术落点只有一个：如何建模"用户已经会什么"。这个选型决定后续所有功能形态，必须先定。以下为三个候选方案（成本/工期为个人项目单人开发的相对量级估算）。

方案实现思路成本复杂度体验风险上线速度综合评价
A. 纯向量检索记忆 把历史对话切片入库，每次讲解前检索相关片段注入上下文，让模型自行"回忆"用户水平 低低中高快 实现最快，但不可解释、不可纠错、会被幻觉污染：模型可能"回忆"出用户没说过的话，且用户无法查看/修正系统对自己的认知
B. 纯结构化画像 维护知识点表 + 掌握度分数，全部决策基于分数规则，不检索原文 中中好中中 可解释、可纠错，但缺少原文支撑：画像说"已掌握极限"，却答不出用户当时是怎么理解的，讲解无法引用先前语境
C. 双轨：结构化画像做决策 + 原文片段做溯源（推荐） 画像条目负责"讲多深"的决策，每条条目挂载证据片段（对话消息 ID / 页码）；讲解时按需检索证据原文注入，不注入全量历史 中中高好低中 推荐：决策链路可解释（为什么这么讲）、可纠错（用户改分数）、可溯源（引用当时原话），同时通过"只检索证据片段"控制 token 成本

5.1 推荐结论

选择方案 C。理由三条：

  1. 方案的差异化本质是"可信的记忆"。方案 A 的记忆不可见不可改，一旦模型记错（把用户问过的问题当成已掌握），用户无从发现，产品最核心的卖点直接崩塌。C 的每条记忆都有证据与来源，错了好改。
  2. 成本可控。C 的注入策略是"画像摘要 + 命中证据片段"，而非 A 的"检索一堆历史对话"或全量回放，单会话成本上限可预估、可封顶（对应 FR-09 的 Token 预算）。
  3. 为后续功能留接口。F5 素材总结需要"按画像裁剪讲义详略"、F4 复习需要"按掌握度与时间排期"，都要求掌握度是可计算的数值而非语言描述——只有结构化画像能提供。

5.2 不选其他方案的原因

  • 不选 A：看似省事，实则把"记忆准确性"完全交给模型，且无法满足"用户可查看/纠错"这一合规与体验双重要求。
  • 不选 B：剖面缺一半——只有"结论"没有"依据"，讲解时无法引用用户此前的原话，复习时也无原文可回看。

5.3 演进路径

阶段记忆策略升级触发条件
本期 V0.5结构化画像 + 关键词命中证据片段（不上向量库，降低依赖）—

6.2 核心使用场景（本期交付）

场景 A：概念学习闭环（主场景）

触发：学习中遇到不懂的概念。频率：每日 1–5 次。

用户提问 → AI 按画像判定深度讲解 → 用户编辑追问 / 要求换讲法 → 满意后存为笔记 → 画像更新。

成功标准：用户不需要说"我已经会 X 了"就能得到合适深度的讲解。

场景 B：笔记阅读与补漏（次场景）

触发：复习已生成笔记时遇到遗忘的术语。频率：每周 2–5 次。

打开笔记 → 划选不认识的词 → 浮层获得简短解释 → "加入笔记"沉淀为术语表条目 / "深入讲解"进入对话。

成功标准：补漏不打断阅读流，且补的漏进入长期记忆。

场景 C：画像校准（低频但关键）

触发：AI 明显讲错深度（讲太浅/太深）。频率：每周 1–2 次。

用户打开画像页 → 查看某知识点的掌握度与来源证据 → 手动下调/上调 → 后续讲解立即改变。

成功标准：用户能在 30 秒内纠正一条错误认知，且不觉得这是"在配置软件"。

七、功能需求（FR）

状态词统一：必须（shall）＝本期不可缺；应该（should）＝本期强力建议；可以（may）＝本期可选；禁止（must not）＝红线。

FR-01基础框架与数据归属

项内容
描述系统必须提供会话列表、对话页、笔记页、画像页、设置页五类页面；用户数据归当前用户所有，可随时导出与删除
业务规则① 本期采用单账号模式（个人项目），但数据结构必须预留 user_id，禁止把用户身份硬编码进业务表
② 会话、笔记、画像条目在删除时必须级联清理（禁止留下孤儿数据）
③ 所有页面在无数据时必须有空状态文案与引导入口
AC-01-1 Given 新用户首次进入，When 打开会话列表，Then 展示空状态与"开始第一个对话"入口，不显示报错。
AC-01-2 Given 某会话下存在笔记与画像证据，When 删除该会话，Then 关联笔记标记为「来源已删除」并保留正文（禁止静默丢失用户内容），画像条目的该条证据被移除并重算掌握度。

FR-02可编辑对话流

项内容
描述用户必须能对任意历史消息执行「编辑」「追加补充」「让 AI 重新响应」；系统必须支持流式输出与消息级重新生成
业务规则① 编辑某条消息后，系统必须基于编辑后的内容重新生成后续响应，并将原响应折叠保留（可见但默认收起）
② 重新生成必须生成新版本而非覆盖（保留 revision 字段，可回退）
③ 编辑不得影响该消息之前的历史
④ 单条消息重新生成必须二次确认（避免误触丢失已有回答）
⑤ 流式输出中断（网络断/用户取消）时，已输出内容必须保留并标注"未完成"，提供重试
AC-02-1 Given 一段 6 轮对话，When 用户编辑第 2 条并选择重新生成，Then 第 3 轮起的响应被新版替换，第 1 条与用户未触及的后续消息不受影响，旧版可通过"查看历史版本"回看。
AC-02-2 Given 流式生成中网络中断，When 恢复连接，Then 页面显示已生成内容 + "生成中断"提示 + 重试按钮，不出现整段空白或重复发送用户消息。

FR-03自适应讲解（画像驱动，核心）

项内容
描述系统必须在每次讲解前读取画像，判定讲解深度档，并可按用户反馈即时调整
业务规则① 前置检查：识别当前提问涉及的知识点 X 及其前置依赖 D₁…Dₙ；若存在依赖掌握度 <0.7，必须先用 1–2 句补齐该依赖再讲 X
② 深度判定：X 掌握度 <0.3 → L0/L1；0.3–0.7 → L1/L2；≥0.7 → L2 并只讲增量（边界、延伸、易错点），禁止重复基础
③ 掌握度初始规则（估算值，按数据调参）：首次出现 0.3；对话中正确应用 +0.2（上限 0.7）；通过复述/自测 0.9；90 天未接触衰减 0.1（下限 0.1）
④ 反馈闭环：讲解下方必须固定提供「再详细些 / 太啰嗦 / 换种讲法」三个入口，点击后立即重新生成并更新画像（对应知识点掌握度 ±0.15）
⑤ 可解释：讲解可展开"为什么这么讲"，展示依据的画像条目
⑥ 禁止：无任何画像证据时不得声称"根据你已掌握的内容"
AC-03-1 Given 画像中"矩阵乘法"掌握度 0.2、"特征值"无记录，When 用户问"什么是特征值"，Then 讲解先补矩阵乘法一句话再进 L1 档讲解。
AC-03-2 Given 用户点击「太啰嗦」，When 重新生成完成，Then 新讲解深度档下降一级，且该知识点掌握度上调 0.15（表示系统此前低估）。
AC-03-3 Given 画像为空（新用户），When 首次提问，Then 使用 L1 默认档，且不出现"根据你的掌握情况"类表述。

FR-04画像查看与纠错

项内容
描述用户必须能查看全部画像条目、掌握度、证据来源，并手动修改或删除
业务规则① 画像页按领域分组，展示知识点名、掌握度（数值 + 可视化条）、最近接触时间、证据数
② 每条必须可展开查看证据（跳转到对应对话消息或笔记位置）
③ 支持手动上调/下调掌握度（步长 0.1）与删除条目；手动修改优先级高于系统推断，30 天内不被自动覆盖（可配置）
④ 禁止在无证据情况下自动写入画像条目（每条必须有 evidence_ref）
⑤ 所有变更留痕（时间、原值、新值、来源：系统推断 / 用户修改）
AC-04-1 Given 某条目由系统推断掌握度 0.8，When 用户手动改为 0.4，Then 画像页显示"由用户设定"，且 30 天内系统推断不覆盖该值。
AC-04-2 Given 用户删除某画像条目，When 再次提问该知识点，Then 系统按"无记录"处理（L1 默认档），不残留旧判定。

FR-05结构化笔记生成与导出

项内容
描述用户必须能将选定对话段一键生成结构化讲义，并导出为 Markdown
业务规则① 生成范围：整个会话或用户框选的消息段
② 讲义结构必须包含：标题、一句话总结、核心概念（每条含定义＋溯源锚点）、例子、常见误区、延伸问题
③ 每条核心概念必须挂溯源锚点，点击可跳回对话原位置
④ 生成过程中必须展示进度；失败时保留已生成部分并允许重试
⑤ 导出 Markdown 必须保留层级标题、锚点（以链接形式）与代码块格式；导出文件名为「会话标题-日期」
⑥ 笔记可二次编辑，编辑后不得静默覆盖原对话（单向引用关系）
AC-05-1 Given 一段 12 轮对话，When 生成笔记，Then 输出的讲义含 ≥3 条核心概念，每条可点击跳回源消息。
AC-05-2 Given 笔记已生成，When 导出 Markdown，Then 文件可直接被常见 Markdown 编辑器渲染，标题层级正确，锚点链接可点击定位。
AC-05-3 Given 笔记生成中途失败，When 用户重试，Then 已生成章节不重复出现（幂等）。

FR-06划词即时解答

项内容
描述用户必须能在笔记阅读视图内划选文本，获得按画像深度调整的即时解释
业务规则① 作用域仅限笔记阅读视图，禁止全局劫持文本选择（不干扰复制）
② 浮层必须在 1.5s 内出现（先出骨架，内容可流式补齐）
③ 浮层包含：简短解释（60–120 字，深度按画像）、「加入笔记」「深入讲解」「换种说法」三个操作、以及原文复制出口
④ 划选超过 200 字时禁止直接解释，改为提示"是否总结此段"
⑤ 无匹配结果时必须明示"未找到相关解释"，禁止编造
⑥ 每次划词必须写入画像信号（该术语接触 +1）
AC-06-1 Given 笔记正文，When 划选"特征值"并停留，Then 1.5s 内浮层展示解释，且解释深度与该词在画像中的掌握度一致。
AC-06-2 Given 用户划选 300 字段落，When 释放鼠标，Then 不出现解释，出现"是否总结此段"提示。
AC-06-3 Given 划选内容为无意义字符串，When 请求解释，Then 明确回复未找到，不生成杜撰内容。

FR-07划词结果加入笔记

项内容
描述用户必须能将划词解答一键沉淀进当前笔记，并可从笔记跳回划词位置
业务规则① 加入位置：当前笔记自动创建的「术语表」章节末尾，或用户指定位置
② 条目格式：术语 + 解释 + 来源（笔记名 + 定位）
③ 同一术语重复加入时必须提示"已存在"，可选择更新解释或跳过（禁止产生重复条目）
④ 加入操作必须可撤销（提供 5 秒内撤销入口）
AC-07-1 Given 笔记中已存在"特征值"术语条目，When 用户再次划词并点击加入，Then 提示已存在并提供"更新解释"，术语表条目数不变。
AC-07-2 Given 用户点击加入后 5 秒内点撤销，Then 术语表恢复到操作前状态。

FR-08画像信号采集与更新

项内容
描述系统必须从五类行为中采集学习信号并更新画像
业务规则信号源与权重（估算，需按数据校准）：
① 提问/追问（识别"什么是 X"类问题 → X 标记为低掌握）——权重 0.3
② 讲解后的深度反馈（太啰嗦/再详细些）——权重 0.4（直接反映系统误判）
③ 划词行为（术语接触）——权重 0.1
④ 笔记生成（提及某概念 → 参与接触）——权重 0.1
⑤ 用户手动纠错——权重 1.0（最高优先，30 天内不被覆盖）
每次更新必须写入变更日志；单次更新幅度上限 0.2，防止单条信号造成剧烈误判。
AC-08-1 Given 用户在某会话中连续 3 次要求"再详细些"，When 第三次反馈完成，Then 该知识点掌握度累计下调（但总幅度不超过规则上限），且后续讲解深度档下降。
AC-08-2 Given 任意画像更新，When 查看变更为日志，Then 可见时间、原值、新值、信号类型四要素。

FR-09成本与降级控制

项内容
描述系统必须控制单会话 token 消耗，并在超限或模型异常时执行降级而非直接报错
业务规则① 单会话 token 预算上限可配置（默认按目标成本 ¥0.5/会话反推）
② 超出 80% 预算时：压缩注入画像（只注入 Top-K 相关条目）、截断非必要历史
③ 超出 100% 预算时：提示用户"本次会话较长，建议开启新会话"，并保留当前会话可读
④ 模型超时/限流时的降级顺序：重试（1 次，指数退避）→ 切换备用模型 → 返回缓存/历史相近讲解并标注 → 明确失败提示
⑤ 禁止在降级时静默返回低质量内容而不标注差别
AC-09-1 Given 单会话消耗达预算 80%，When 用户继续提问，Then 系统按压缩策略注入上下文，响应正常但画像注入条目数减少（可在调试面板查看）。
AC-09-2 Given 主模型返回 429，When 触发降级，Then 用户看到"已切换备用模型"提示，而非"系统繁忙"。

7.8 AI 能力专项（六模块）

模块本产品定义
任务定义谁：学习者；何时：遇到不懂的概念或复习遗忘点时；基于：当前提问 + 画像条目 + 命中证据片段；目标：给出**贴合当前水平**的解释，并留下可复习的结构化产物；AI 定位是"讲解者 + 整理者"，不是替用户学习（最终判断与笔记取舍由用户完成）
输入与上下文契约输入包含：用户消息、画像摘要（Top-K 相关条目）、命中证据片段（≤3 条）、当前笔记上下文（若从笔记发起）。冲突处理：用户当下表述与画像冲突时以用户当下为准并立即修正画像；缺失关键信息（如前置概念完全未知）时先用一句话补齐而非追问；超长输入按段落摘要后进入
输出契约讲解：结构化 markdown（概念 / 例子 / 易错点 / 与已学内容的连接），深度档显式标注；笔记：固定六段结构（标题/总结/核心概念/例子/误区/延伸），每条核心概念必带 evidence_ref。禁止输出：无来源的确定性断言、超出学科范围的投资/医疗建议、编造引用文献
质量标准与验收样本质量维度：事实正确 / 深度档匹配 / 结构合规 / 溯源可验证 / 无幻觉。
验收样本集：≥20 条，覆盖「常见概念」「画像命中」「画像冲突」「前置缺失」「超长输入」「无匹配划词」「拒答场景」七类；每类给可接受/不可接受样例。
量化阈值（估算）：事实正确率 ≥95%（20 条抽样人工校验）、深度档判定与用户反馈一致率 ≥80%、溯源锚点有效率 =100%
异常降级与人工接管见 FR-09 降级顺序；划词无匹配 → 明示未知；画像冲突 → 以用户为准 + 修正；模型拒答 → 说明原因并给替代路径（换角度提问建议）。由于是个人单用户产品，无"人工客服接管"，改为「用户即接管者」：所有降级点必须提供清晰的手动操作出口
反馈与版本闭环字段级反馈：深度反馈（三按钮）、笔记条目编辑记录、划词"换种说法"次数。
每条生成结果关联：model_version / prompt_version / profile_snapshot_id，可复现当时为什么这样讲；灰度对比按 prompt_version 分组统计采纳率

九、业务流程与状态流转

9.1 主流程：概念学习闭环（对应场景 A）

  1. 用户发送提问 → 系统识别知识点 X 与前置依赖 D
  2. 读取画像 → 判定深度档 → 组装上下文（画像 Top-K + 证据片段）→ 流式生成讲解
  3. 用户反馈：满意（继续）／太啰嗦／再详细些／换种讲法 → 后三者触发重新生成 + 画像更新
  4. 用户点「存为笔记」→ 选择范围 → 生成结构化讲义（带溯源锚点）
  5. 画像更新（讲解涉及的知识点全部计入接触记录）
  6. 后续进入笔记阅读场景（场景 B），划词补漏回流

9.2 状态机

① 消息状态

状态触发事件迁移条件允许操作
正常生成完成用户编辑 → 已编辑；重生成 → 已重生成编辑 / 追加 / 重生成 / 复制 / 折叠
流式中用户发送或重生成完成 → 正常；中断 → 未完成；取消 → 未完成取消生成
未完成网络中断 / 用户取消 / 超时重试成功 → 正常重试 / 保留 / 删除
已编辑用户修改内容触发重生成 → 后续消息进入已重生成查看历史 / 重生成 / 还原
已重生成基于编辑后的内容重新响应再次编辑 → 循环；确认 → 正常查看旧版 / 切换版本

② 笔记状态

状态触发事件迁移条件允许操作
生成中用户点「存为笔记」成功 → 草稿；失败 → 生成失败取消
草稿生成成功用户编辑保存 → 草稿；导出 → 已发布编辑 / 重新生成 / 删除 / 导出
已发布首次导出或手动标记继续编辑 → 草稿（生成新版本）导出 / 编辑 / 查看版本
生成失败模型异常 / 超时重试成功 → 草稿重试 / 查看已生成部分 / 删除
来源已删除源会话被删除终态（内容保留，标记来源缺失）阅读 / 导出 / 删除

③ 画像条目状态

状态触发事件迁移条件允许操作
候选采集到信号但证据不足证据数 ≥1 且通过校验 → 生效查看 / 忽略
生效校验通过写入90 天无接触 → 衰减；用户纠错 → 已纠错修改掌握度 / 查看证据 / 删除
衰减定时任务（每日）新增接触 → 生效同上
已纠错用户手动修改30 天保护期结束 → 生效再次修改 / 查看变更历史

9.3 关键判断分支

  • 是否有画像证据？无 → 用默认档 L1 且不声称"根据你的情况"；有 → 按规则判档。
  • 前置依赖是否缺失？缺失 → 先补依赖再讲（1–2 句），不打断主问题。
  • 用户反馈是否与画像冲突？冲突 → 以用户反馈为准，画像立即修正。
  • 是否超出 token 预算？是 → 按 80%/100% 两档执行压缩与提示。

十一、权限与安全要求

项要求
账号模式本期单账号（个人项目）。数据结构必须含 user_id，所有查询强制带 user_id 条件，为后续开放注册预留隔离能力；禁止依赖"只有一个人用"这一假设写死逻辑
密钥管理模型 API Key 仅存服务端环境变量，禁止出现在前端代码、日志、错误堆栈；前端所有模型调用走后端代理
数据访问用户数据（会话/笔记/画像）仅本人可读；无管理员后台读取功能（个人项目初版不做，后续如需再加）
用户权利必须提供一键导出全部数据（JSON + Markdown）与彻底删除（含 AILog 中的会话内容）；删除后 30 天内不清除备份的需明确告知
日志脱敏AILog 只存元信息（token 数、时延、版本），不存消息正文；错误日志中如含用户内容必须截断并脱敏
内容安全讲解内容禁止输出违法、涉政敏感、色情暴力内容；涉及医疗/法律/投资等专业领域时必须声明"仅供学习理解，不构成专业建议"
第三方内容用户上传的 PDF/视频（V0.6 起）仅限个人学习使用，界面需提示"请确认你拥有该内容的合法使用权"；不提供下载、二次分发能力
未成年人若后续开放注册面向未成年人，需补充监护人同意流程与使用时长提示；本期单用户自用不涉及

编号异常场景系统行为用户可见反馈恢复方式

13.1 依赖就绪度评估（三档分级）

依赖项所属分级说明 / 最晚就绪 / 替代方案
大模型 API（讲解 + 笔记生成）第三方服务阻塞核心能力，无模型即无产品。最晚于 B1 批次开始前确认可用；必须支持多供应商切换（同一抽象接口），单一供应商涨价/限流可直接替换
流式输出能力（SSE）技术方案阻塞不做流式则首字时延目标（≤3s）无法达成，体验不可接受；无替代

向量检索 / Embedding技术方案可绕过本期用关键词命中替代（方案 C 的初版形态），不上向量库；召回不够时 V0.6 再引入

图形渲染（SVG 生成）技术方案可绕过V0.6 启动；本期无图形需求

13.3 上线后验证（自用 dogfooding 阶段）

  • 连续自用 14 天，记录每日闭环完成次数与中断原因
  • 第 7 天与第 14 天各做一次「同一概念两次讲解对比」——检查是否真的"越用越懂我"
  • 第 14 天复盘：画像覆盖率、讲解采纳率、笔记产出率是否达 2.3 节目标；未达标则先修核心再谈新功能

  • 若邀请 3–5 位同学试用，需补充：多账号隔离验证、隐私说明告知、使用边界说明

15.2 核心页面线框思路

页面名称：对话页

目标：让用户一次就拿到"贴合我水平"的讲解，并顺手沉淀。

布局：

  • 左侧（可收起）：会话列表
  • 主区上方：会话标题 + 画像状态提示（"依据 12 条已掌握知识点" 可点开查看）
  • 主区：消息流。AI 消息底部固定三条反馈（再详细些 / 太啰嗦 / 换种讲法）+「为什么这么讲」折叠入口
  • 主区底部：输入框（吸底）+「存为笔记」快捷按钮

交互说明：

  • 用户消息 hover 出现「编辑」，点击进入行内编辑，保存后弹出"是否让 AI 重新回答？"
  • 流式中显示光标与停止按钮；中断显示重试条
  • 画像为空时顶部不显示画像提示条（避免"假装懂你"）
  • 超长会话达预算 80% 时输入框上方出现轻提示，不阻断

页面名称：笔记页（阅读视图）

目标：让用户能顺畅复习，遇到遗忘点当场补，补完就沉淀。

布局：顶部（笔记标题 + 导出 + 编辑）｜正文区（六段结构，核心概念右侧有锚点小图标）｜末尾术语表｜右下角"回到对话原文"浮动入口。

交互说明：

  • 划词 → 浮层（解释 + 加入笔记 / 深入讲解 / 换种说法 + 复制）
  • 点锚点图标 → 侧滑显示对话原文片段，不整页跳走
  • 术语表条目可删除，删除后原文中的标记同步消失
  • 空状态：无笔记时展示"从对话生成第一篇笔记"引导

页面名称：画像页

目标：让用户 30 秒内看懂"AI 认为我会什么"，并能改掉错的。

布局：顶部概览（条目总数 / 本领域分布 / 最近更新）｜列表（知识点 · 掌握度条 · 最近接触 · 证据数）｜右侧详情抽屉（证据列表 + 掌握度调整 + 删除 + 变更历史）。

交互说明：

  • 掌握度调整用 ±0.1 步进按钮 + 滑块，保存后立即生效
  • 用户修改过的条目显示"由你设定"标签，并显示保护期剩余天数
  • 证据点击跳转到对应消息并高亮
