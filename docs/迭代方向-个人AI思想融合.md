# 迭代方向 · 个人 AI 前沿思想融合（Muse / Grok 启发）

> 基于 2026-09/10 的产品调研（Muse = Meta 个人 AI 代理；Grok = xAI 陪伴型助手）。
> **实施状态（批次 F1，2026-10-26；F1+ 增强 2026-10-28）**：方向 1（记忆回现）、3（人格可调）、6（完成通知）、2（洞察卡）已交付；F1+ 增强：苏格拉底人格升级为**多轮引导流程**（开启轮只给方向+抛问题 → 续轮反馈/递进 → 【学习复盘】收尾，状态存 meta.socratic_state，复盘后自动回归正常模式）；4（语音）、5（联网检索）按依赖情况延后。

## 核心判断：可以融合，且 PAI 有独特优势

Muse 与 Grok 的两大共性思想——**Active Memory**（记住细节并在相关时回现）与**持久个性化**——PAI 已经用"知识画像"实现了学习领域版本，而且 PAI 的记忆**透明、可纠错、有证据链**（画像页），比 Muse 的黑盒记忆在信任维度上更强。当前缺的是四个能力层：**主动层、人格层、语音层、联网层**。以下六个方向按建议顺序排列。

---

## 1 · 记忆回现增强 ← Muse「Active Memory」 【量级 S · 建议下一批】

**产品思想**：Muse 把用户只提过一次的细节记住，在相关任务时主动带回来。
**PAI 落点**：讲解开头自然回现历史——"你上周问过特征值，当时还问了矩阵乘法，这次我们直接往深处走"。
**现有地基**：`loadEvidenceSnippets` 已在讲解时注入 ≤3 条历史证据（B2 实现），但只在"为什么这么讲"面板里可见。
**改动**：prompt 增加指令——有证据片段时，讲解第一段用一句自然的话回现（"接着我们上次聊的 X"），替代生硬开头。与画像的可解释性互相强化。
**风险**：无。纯 prompt 层。

## 2 · 主动学习洞察 ← Muse「Proactive」 【量级 M】

**产品思想**：Muse 主动帮人达成目标、建议下一步。
**PAI 落点**：首页"今日学习建议"卡——完全数据驱动的 3 条建议：①复习队列里有到期的卡片；②某概念 90 天衰减临近；③划词多次但你从未深入的概念（"你三次划选了'特征多项式'，要不要系统学一下？"）。
**现有地基**：review_logs / profile_logs / selection_events 三张表的数据都在，只缺一个聚合建议的接口 + 首页卡片。
**与 PRD 关系**：不越 F4 触发条件——F4 是"定时推送+陪伴"，本方向是"进入应用时的数据洞察卡"，无推送承诺。

## 3 · 导师人格可调 ← Grok「Persona」 【量级 S】

**产品思想**：Grok 的陪伴角色有固定人设与语气，情绪一致性强。
**PAI 落点**：设置页选择讲解语气——**苏格拉底式**（先反问引导你自己推）、**教练式**（鼓励 + 类比丰富）、**极简式**（要点化，不寒暄）。实现为 explain prompt 的 persona 段落，存 settings（复用 token_budget 的 kv 模式）。
**现有地基**：prompt 版本化（EXPLAIN_PROMPT_VERSION）+ L0–L2 深度档已是人格层的骨架。
**注意**：人格切换影响采纳率指标，切换时建议在指标面板标注"人格变更"事件（可从 settings 变更推导）。

## 4 · 语音学习 ← Grok「Voice」/ Muse 多模态 【量级 M】

**产品思想**：Grok 陪伴角色语音对话；Muse 多模态输入。
**PAI 落点**：浏览器原生 Web Speech API（零新依赖）——①对话页语音输入提问（SpeechRecognition，Chrome/Edge 支持）；②笔记阅读页"朗读"按钮（speechSynthesis，通勤/睡前复习场景）。
**现有地基**：对话页与笔记页结构稳定，只需加输入法切换与朗读控件。
**限制**：浏览器兼容（Firefox 不支持 SpeechRecognition）需特性检测降级。

## 5 · 可选联网检索 ← Grok「Real-time」 【量级 M】

**产品思想**：Grok 的实时 X/网络检索保证答案不过时。
**PAI 落点**：讲解时可选联网核实——通用学科知识大多稳定，但"最新标准/版本/事件"类问题需要联网；设置页开关 + 供应商接入（如博查/Tavily/SearXNG，另列依赖项进 PRD 13.1 表）。
**现有地基**：explain 管线的上下文组装点已预留（插入检索结果段即可）；输出契约已有"禁止编造"红线，联网后加"标注来源"。
**注意**：引入第三方依赖与费用，建议排在人格/语音之后。

## 6 · 完成通知 ← Muse「Background Tasks」 【量级 S】

**产品思想**：Muse 有自己的持久环境做后台任务。
**PAI 落点**：笔记生成/追加/合并是异步长任务（10–30 秒），用户经常切走——完成后 Web Notification 提醒 + 点击跳转。纯前端 Notification API，无服务端推送。
**现有地基**：生成流程已在后台异步执行；只需权限请求 + 完成回调。

---

## 建议实施顺序

**1（记忆回现）→ 3（人格）→ 6（通知）** 三个 S 级先做，一个批次搞定；**2（洞察卡）** 随后（数据已齐）；**4（语音）**、**5（联网）** 按需。每个方向实施前建议先过一遍复盘指标（docs/待办迭代-复盘指标.md）确认基础盘。

## 与现有 PRD 的关系

- 不改变 B1–B5 / N1–N5 已交付能力，全部为增强层
- 不触发 F4 完整版（方向 2 无推送、方向 6 是本地通知）
- 方向 5 需在 PRD 13.1 依赖表新增"搜索 API"条目（另列）
- PAI 差异化定位保持：**透明可纠错的学习记忆**——这是 Muse/Grok 都没有的
