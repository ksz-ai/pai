# PAI 智能助手 · 模块说明

> 版本：v1.0 · 2026-10-30  
> 定位：在不改动原型既有功能的前提下，为全部页面新增一个类 Trae Bot / Grok Bot 的全局浮层智能对话助手。

---

## 1. 模块概览

智能助手以右下角悬浮入口的形式常驻在所有页面，点击后展开一个停靠式对话面板。面板包含：

- 自然语言输入框（Enter 发送、Shift + Enter 换行、自动增高）
- 实时响应区（思考中指示 + 逐字流式输出 + 光标 + 可停止）
- 快捷操作指令面板（6 个快捷指令 + 9 个 `/` 斜杠指令，支持键盘上下选择）
- 上下文记忆（页面 / 概念 / 话题三类记忆标签，跨页面保留，回答尾部展示引用来源）

助手不修改任何原有页面结构与交互，仅在每个页面追加一个样式文件和一个脚本文件。

## 3. 需求实现对照

| 需求 | 实现方式 |
| --- | --- |
| 自然语言交互输入框 | `#pa-input` 多行输入，Enter 发送、Shift + Enter 换行、输入自动增高、空内容禁用发送 |
| 实时响应输出区域 | 先显示三点「正在思考」，再以 3 字符 / 18ms 的节奏逐字渲染，带闪烁光标；生成中发送按钮变为「停止」 |
| 快捷操作指令面板 | 面板内常驻 6 个快捷指令；点击「全部指令 / 输入 `/`」打开 9 条斜杠指令面板，支持 ↑↓ 选择、Enter 执行 |
| 上下文记忆能力 | 三类记忆标签 + `sessionStorage` 持久化 + 跨页面切换提示 + 每条回答的「引用」来源 |
| 视觉风格统一 | 复用 `--primary / --surface / --border / --r-* / --sh-* / --font-*`，沿用卡片、标签、按钮、虚线分隔等既有语言 |
| 全尺寸响应式 | `>900px` 右下停靠浮层；`≤900px` 收窄并贴边；`≤560px` 全屏面板并锁定背景滚动 |
| 不影响原有功能 | 独立前缀、独立存储键、独立事件监听；弹窗 z-index 60 仍高于助手 58，Toast 80 仍最高 |

## 4. 交互说明

### 唤起与关闭

- 点击右下角「智能助手」按钮，或按 `Alt + A` 切换
- 在「对话讲解」页，入口自动收为圆形图标并上移到输入区上方，避免遮挡原有发送按钮
- 点击面板右上角 `×` 或按 `Esc` 关闭；若页面弹窗正在打开，`Esc` 优先关闭弹窗
- 移动端展开时面板全屏，并锁定页面背景滚动，收起后恢复

### 对话

- 输入内容后发送，先出现「正在思考」，随后流式输出回答
- 生成中点击「停止」可中止，已生成部分保留
- 每条助手回答支持「复制」「重新生成」
- 顶部 `+` 可开始新对话：清空消息与概念记忆，只保留当前页面上下文

### 跨页面

- 从任意页面通过原有导航切换后，助手消息与概念记忆保留
- 新页面首次展开时，会插入一条系统提示：`已切换到「笔记库」，保留 N 条上下文记忆`
- 页面切换只更新「页面」记忆标签，不清空其他记忆

## 5. 上下文记忆机制

### 存储键（会话级，按浏览器标签页隔离）

| Key | 内容 |
| --- | --- |
| `pai.assistant.messages.v1` | 最近 16 条用户 / 助手消息 |
| `pai.assistant.context.v1` | 记忆标签数组 |
| `pai.assistant.page.v1` | 上次所在页面标识，用于生成跨页提示 |

`sessionStorage` 在同一标签页的页面跳转间共享，刷新保留，新开标签页重置；所有读写都包裹 `try/catch`，隐私模式下静默降级。

### 记忆标签

| 类型 | 来源 | 上限 | 是否可移除 |
| --- | --- | --- | --- |
| `page` | 当前页面（学习概览 / 笔记阅读 / 复习队列…） | 1 | 否 |
| `concept` | 从消息中识别出的画像概念（如 RoPE、置换不变性） | 最多 4 个非页面标签 | 是 |
| `topic` | 未命中概念时的最近话题（截断 12 字） | 1 | 是 |

- 记忆总数限制为「页面 + 4 项」，超出时移除最早的项
- 每条助手回答尾部展示「引用 本页 · 笔记阅读 / RoPE」等标签，直观体现上下文被使用
- 「继续 / 接着 / 再讲」类消息会保留原话题并生成承接式回答
- 点击标签右侧 `×` 可单独移除；「新对话」可整体重置

## 6. 指令一览

| 指令 | 说明 |
| --- | --- |
| `/explain` | 解释当前页面的核心概念 |

| `/profile` | 列出掌握度最低的概念 |
| `/plan` | 结合画像生成 20 分钟学习计划 |
| `/notes` | 列出置顶与最近笔记 |
| `/help` | 查看全部指令 |

除斜杠指令外，也支持自然语言，例如「帮我出三道题」「今天有哪些概念到期」「继续讲相对位置」。

## 7. 回复引擎与真实接入

当前版本使用 `assistant.js` 内的本地规则引擎（`composeReply`），回答数据来自 `mock.js`（概念掌握度、复习队列、笔记卡片等），不调用任何真实模型。

意图路由顺序：帮助 → 问候 → 复习 → 最弱概念 → 学习计划 → 方案对比 → 自检题 → 总结 → 承接上文 → 笔记 → 概念解释 → 默认上下文回答。

### 接入真实后端时

1. 将 `composeReply(text)` 替换为真实的流式请求（如 `fetch` + SSE / AI SDK）。
2. 保留 `startStream(reply)` 的渲染接口：只需把增量文本持续写入 `reply.text`，即可继续复用逐字渲染、停止、复制、引用与持久化能力。
3. 请求体建议携带：`{ page, message, context: state.context, history: state.messages.slice(-8) }`，与现有 `Mock 服务层` 的约定一致。
4. 无需改动 CSS 与页面结构；`assistant.js` 是唯一需要替换的数据边界。

## 8. 兼容性与可访问性

- 所有新组件使用 `pa-` 前缀，不覆盖原页面类名
- 仅在 7 个页面追加 `<link>` / `<script>`，原有内联脚本和事件绑定零改动
- 助手层 `z-index: 58`；页面弹窗 60、Toast 80，保证原有弹层不被遮挡
- 不使用 `data-modal-open` / `.segmented` 等原共享组件选择器，避免与 `app.js` 全局委托冲突
- 输入框、按钮、指令面板均含 `aria-label` / `role`，支持键盘操作与 `Esc`
- 尊重 `prefers-reduced-motion`：关闭浮层、光标与状态点的动画
- 启动器会测量页面底部的 `.composer-wrap` 并动态上移，输入区增高时通过 `ResizeObserver` 重新避让

## 10. 已知限制

- 回答由本地规则生成，不具备真实大模型的开放域推理能力
- 上下文按浏览器标签页隔离，新开标签页会重新开始
- 流式输出为前端模拟，暂未接入 Token 预算统计
- 移动端采用全屏面板，展开时会覆盖页面内容，这是类 Grok Bot 的预期行为
